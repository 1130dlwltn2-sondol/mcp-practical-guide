# 12. 핵심 개념

MCP를 이해하려면 다섯 가지 개념을 잡아야 합니다.

첫째, JSON-RPC 2.0입니다. MCP의 메시지는 모두 JSON-RPC 2.0 형식입니다. 요청과 응답, 알림(응답이 필요 없는 메시지)으로 구성됩니다. 프로토콜의 뼈대이니 이름만 알아두세요. SDK가 대부분 처리해 줍니다.

둘째, 데이터 계층과 전송 계층입니다. 데이터 계층은 "무엇을 주고받는지"를 정합니다. 도구 목록 조회, 도구 실행 같은 내용입니다. 전송 계층은 "어떻게 주고받는지"를 정합니다. 로컬 프로세스 간 통신인지, HTTP로 원격 통신인지 같은 것입니다. 내용은 같고 길만 다른 구조입니다.

셋째, discovery입니다. 클라이언트는 서버에 "네가 뭘 할 수 있니?"라고 먼저 묻습니다. server/discover 요청에 서버가 지원하는 버전과 기능을 답합니다. 클라이언트는 이 정보를 보고 사용 가능한 도구 목록을 가져옵니다.

넷째, 상태 비저장입니다. 각 요청은 독립적으로 처리됩니다. 서버가 이전 요청을 기억하고 있을 거라 기대하지 않습니다. 필요한 정보는 매 요청에 담깁니다.

다섯째, 알림입니다. 서버의 도구 목록이 바뀌면 클라이언트에게 알립니다. 클라이언트는 관심 있는 알림 종류를 구독해 둡니다. 실시간으로 바뀌는 정보를 반영하는 장치입니다.

이 개념들은 뒤에서 계속 나옵니다. 지금은 이름과 역할만 익혀 두세요.

핵심 정리
- 메시지는 JSON-RPC 2.0, 계층은 데이터와 전송으로 나뉜다.
- discovery로 서버의 기능을 파악하고, 요청은 상태 비저장으로 처리한다.
- 알림으로 변경 사항을 실시간 반영한다.
