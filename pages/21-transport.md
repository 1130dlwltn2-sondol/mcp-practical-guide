# 21. 전송 방식

MCP는 두 가지 전송 방식을 지원합니다. 어디에서 서버를 돌리느냐에 따라 고릅니다.

Stdio는 표준 입출력으로 통신하는 방식입니다. 로컬에서 서버 프로세스를 직접 띄우고 파이프로 주고받습니다. 같은 컴퓨터 안에서 도는 서버에 씁니다. 네트워크가 없어서 빠르고 설정이 단순합니다. Claude Desktop에서 로컬 파일 서버를 연결하는 것이 대표 예입니다. 단점은 한 클라이언트만 쓸 수 있다는 것입니다.

Streamable HTTP는 HTTP로 통신하는 방식입니다. 원격 서버에 씁니다. 클라이언트가 HTTP POST로 메시지를 보내고, 필요하면 서버가 스트리밍으로 답합니다. 여러 클라이언트가 동시에 쓸 수 있습니다. 팀이나 조직 단위로 서버를 공유할 때 씁니다. 인증은 Bearer 토큰이나 API 키, 커스텀 헤더를 쓰고, 공식적으로는 OAuth를 권장합니다.

선택 기준은 간단합니다. 개인이 자기 컴퓨터에서 쓰는 도구는 stdio입니다. 팀이 함께 쓰는 서비스는 Streamable HTTP입니다. 개발할 때는 stdio로 시작해서, 공유할 때 HTTP로 바꾸는 순서가 일반적입니다.

참고로 예전에는 SSE(Server-Sent Events) 전송 방식도 있었지만, 현재는 Streamable HTTP로 통합되는 추세입니다. 새 서버를 만든다면 Streamable HTTP를 기준으로 하세요.

핵심 정리
- Stdio는 로컬용, Streamable HTTP는 원격용이다.
- Stdio는 빠르고 단순하지만 한 클라이언트만 쓴다.
- 원격 서버의 인증은 OAuth가 권장된다.
