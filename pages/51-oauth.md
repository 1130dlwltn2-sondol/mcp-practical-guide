# 51. OAuth 인증

원격 MCP 서버는 인증이 필수입니다. 공식적으로 권장되는 방식은 OAuth입니다.

흐름은 일반적인 OAuth와 같습니다. 클라이언트가 서버에 연결하면, 서버는 인증이 필요하다고 알립니다. 클라이언트는 사용자를 인증 서버로 보내 로그인하게 하고, 토큰을 받아옵니다. 이후 요청에는 토큰을 담아 보냅니다. 서버는 토큰을 검증하고 요청을 처리합니다.

서버를 만들 때는 토큰 검증을 먼저 붙입니다. 어떤 토큰을 믿을지, 만료된 토큰은 어떻게 처리할지 정합니다. 사용자별로 권한이 다르면, 토큰에서 사용자를 식별해 도구 접근을 제한합니다. 예를 들어 읽기 도구는 모두에게, 쓰기 도구는 특정 팀에게만 여는 식입니다.

개발 중에는 간단한 Bearer 토큰으로 시작해도 됩니다. 하지만 운영에서는 OAuth로 올리는 것이 권장됩니다. 토큰 탈취에 대비해 만료 시간을 짧게 하고, 갱신 토큰을 씁니다. 로그에는 토큰 값을 남기지 않습니다.

클라이언트 쪽 설정도 필요합니다. Claude Code 같은 클라이언트는 MCP 서버 설정에 인증 정보를 넣습니다. 토큰은 설정 파일에 직접 적지 말고 환경 변수나 비밀 관리자를 씁니다.

핵심 정리
- 원격 서버의 인증은 OAuth가 권장된다.
- 토큰 검증과 사용자별 권한을 서버에 구현한다.
- 토큰은 환경 변수로 관리하고 로그에 남기지 않는다.
