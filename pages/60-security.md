# Part 6. 운영과 보안

## 60. 보안 고려사항

MCP 서버는 AI가 외부 세계와 만나는 지점입니다. 보안이 중요합니다.

첫째, 도구 권한입니다. 도구는 AI가 실행하는 함수입니다. 삭제나 전송 같은 위험한 도구는 신중하게 제공합니다. 읽기 전용으로 충분하면 쓰기 도구는 만들지 않습니다. 꼭 필요하면 Elicitation으로 사용자 확인을 받습니다.

둘째, 입력 검증입니다. AI가 만드는 입력값이 항상 올바르다고 가정하지 않습니다. 모든 입력은 서버에서 검증합니다. 파일 경로는 허용된 디렉토리 안인지 확인합니다. SQL은 파라미터 바인딩을 씁니다. 명령어 실행 도구는 인자를 엄격히 제한합니다.

셋째, 비밀 관리입니다. API 키와 토큰은 환경 변수나 비밀 관리자에 둡니다. 코드와 설정 파일에 직접 적지 않습니다. 로그에 비밀값이 찍히지 않게 합니다. 저장소에 올리기 전에 비밀값이 없는지 확인합니다.

넷째, 원격 서버의 인증과 권한입니다. OAuth로 사용자를 식별하고, 사용자별로 쓸 수 있는 도구를 제한합니다. 관리자 도구와 일반 도구를 분리합니다. 접근 로그를 남깁니다.

다섯째, 서드파티 서버 주의입니다. 남이 만든 MCP 서버를 쓸 때는 무엇을 하는지 확인합니다. 도구가 어떤 권한을 요구하는지 봅니다. 신뢰할 수 없는 서버는 쓰지 않습니다. 클라이언트의 승인 설정을 켜 둡니다.

보안은 한 번에 끝나는 게 아닙니다. 서버를 바꿀 때마다 이 체크리스트를 다시 봅니다.

핵심 정리
- 위험한 도구는 만들지 않거나 확인을 받는다.
- 입력은 항상 검증하고, 비밀값은 코드에 두지 않는다.
- 원격 서버는 OAuth와 사용자별 권한으로 보호한다.
