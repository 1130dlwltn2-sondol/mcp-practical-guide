# 61. 운영과 모니터링

서버를 만들었으면 운영이 남습니다.

로깅은 기본입니다. stdio 서버는 stderr에 로그를 남깁니다. stdout은 프로토콜 메시지가 오가니 건드리지 않습니다. HTTP 서버는 OpenTelemetry 같은 표준을 씁니다. 로그에는 요청, 에러, 실행 시간을 남기고, 비밀값은 빼고 남깁니다.

모니터링 항목입니다. 서버가 살아 있는지 헬스 체크합니다. 도구별 호출 수와 실패율을 봅니다. 응답 시간이 느려지면 원인을 찾습니다. 에러가 늘면 알림을 받습니다.

버전 관리도 필요합니다. 도구를 바꾸면 기존 클라이언트에 영향이 갑니다. 입력 형식을 바꾸는 것은 호환성이 깨지는 변경입니다. 새 버전의 도구를 추가하고, 예전 것은 일정 기간 유지한 뒤 제거합니다. 변경 사항은 문서로 남깁니다.

장애 대응입니다. 서버가 죽으면 클라이언트는 연결 실패로 표시합니다. 자동 재시작을 걸어 둡니다. 상태 비저장 설계를 지켰다면, 재시작해도 요청 처리에 문제가 없습니다. 장애 원인은 로그에서 찾습니다.

운영 체크리스트
- 헬스 체크 엔드포인트가 있는가
- 로그에 비밀값이 없는가
- 도구 변경 시 호환성을 고려했는가
- 자동 재시작이 걸려 있는가

핵심 정리
- stdio는 stderr에, HTTP는 표준 방식으로 로그를 남긴다.
- 호출 수, 실패율, 응답 시간을 모니터링한다.
- 도구 변경은 호환성을 지켜 점진적으로 한다.
